# cursor-harness-provider development contract
One Rust core for Pi and OpenCode. Remote creation, commits and pushes require task authorization. The user has explicitly authorized unattended npm releases for this repository: accepted distributable-code changes on main may automatically create a version commit/tag and publish after required CI succeeds. Other branches do not authorize publication. Installed-plugin switches still require separate explicit authorization. Ordinary task; do not create/focus persistent goals. Existing installed plugins must remain untouched until verification. Never open/copy auth.json, tokens or OS credentials; test with fixtures. No toolchain installation or global PATH/registry changes.

## Layout/ownership
- crates/cursor-core: pure Rust engine/protocol/transport/journal/prost; no N-API dependencies.
- crates/cursor-node: Node-API binding only; futures own Rust values (do not use napi2 async &self).
- packages/native: shared loader/typed API; RustEngine interface stays compatible with existing start(JSON,token),listModels(token,url?),remove(scope),shutdown; RustStream.nextEvent/cancel/setAccessToken. Version from package manifests (not hardcoded).
- packages/opencode: adapter with same providerID cursor-native and existing OAuth method; import runtime from @cursor-harness-provider/native. Never import Pi runtime/JS protocol engine.
- packages/pi: Pi provider cursor, API cursor-native-rust (avoid globally overriding old API until actual replacement), imports runtime from @cursor-harness-provider/native. Thin conversion/lifecycle/auth/UI only, no JS HTTP2/Connect/protobuf inference/CLI. Pi host libraries peer(*) and external, never bundle.
- vendor/pi-cursor: unmodified MIT upstream1.4.39 at ef3cafb5c38081ce6e06df8e594241aabd9621e3 source reference, auth/UI helpers may be reused with attribution, not stream/client inference. test/reference/pi-cursor is the old ported TS implementation for test oracles only.
- scripts/build.mjs main agent; Rust scripts core worker; OpenCode-specific dev scripts OpenCode worker.

## Safety/compatibility
Account/workspace/model/session/request-kind isolation; add host namespace so Pi/OpenCode cannot share checkpoints. Keep tools at each host permission gate; never perform native file/shell/fetch actions. Maintain conservative uncertain-action/partial-output retry, mixed protobuf oneof failclosed, alone observed update27 ignored without progress/finish. Preserve NAPI rejected receiver GC and SDK activation nonce/retry:false. No live Cursor calls by workers. No push/commit/create remote by workers.
Use existing configured Cargo-home or PATH-selected Rust tools with command-local env only; never install tooling automatically. Keep rustup proxy basenames intact. Set CARGO_TARGET_DIR to a known external Cargo cache when reusing earlier build outputs; no target directory inside the watched repository. Until independent package versioning is explicitly implemented, root, all packages, Cargo and native versions must match; the native package/manifest/binary versions must always agree.
The user has explicitly authorized automated direct OIDC publication, automatic coordinated versions/changelogs/tags, necessary CI/configuration/source commits and an initial 0.3.1 acceptance release. Ordinary releases must not wait for a release PR, GitHub reviewer or npm staged approval. Keep pack-utils offline pack/install only. Only the repository's publish.yml workflow at a matching immutable release tag, with automation enabled and all same-run native builds, aggregation and actual packed-host gates successful, may write the registry. Keep npm-release as a ref-restricted identity boundary but remove its recurring human reviewer requirement during the authorized migration. Enable only needed Trusted Publisher actions; do not disable account 2FA, introduce npm/PAT secrets, automate security-key/2FA presence, switch installed plugins or reuse a binary under a different version. Initial account/trust changes may still require the owner once. Version preparation uses a narrowly scoped GITHUB_TOKEN and explicit workflow dispatch, not assumptions about bot pushes triggering another workflow. Preserve source commit/run/attempt/lock/hash/license bindings and every supported target's actual host acceptance. Reconcile ambiguous writes by reading the registry; never blindly republish, overwrite, unpublish or move latest backward. Public integrity/signature/provenance and isolated installation verification must run automatically after publication. Already-published dependency reuse needs explicit immutable version/hash/provenance evidence, not fictitious same-run build claims. The earlier one-time bootstrap is complete: its token was revoked and environment Secret removed; do not recreate either, rerun bootstrap or approve 0.0.0-bootstrap candidates. No automatic rejection/unpublish of historical candidates. No long-lived publication credentials.
Return limitations honestly. Do not advertise advanced Pi capabilities without implemented routing/tests. Check the installed Pi docs (packages.md, custom-provider.md, extensions.md and sdk.md) and examples before changing the extension API.
